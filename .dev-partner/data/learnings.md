# learnings — 成功例・失敗例

着手前（手順0）に必ず読む。この中から今回守るべきものを宣言してから始める。
新しいIDは `dp.py next-id learning` で取得する。

書式:
```
## L-xxx [成功|失敗] 一言タイトル（YYYY-MM-DD / P-xxx or B-xxx）
- 状況:
- 何が起きたか:
- 原因分類: 指示の曖昧さ｜検証不足｜感覚的な調整｜知識不足｜繰り返し作業（成功例は「うまくいった理由」）
- 次回のルール: （次に同じ状況になったら何をするか。1〜2行）
- 対応: （作成・改善したツール、SKILL の変更など。なければ「なし」）
```

## L-001 [成功] 揮発する ~/.claude は実体をリポジトリに置き、リンクで見せる（2026-11-19 / P-000）
- 状況: dev-partner の置き場所に `~/.claude/` を指定された。作業環境はクラウドのコンテナで、セッションが終わると `~/.claude` は消える。
- 何が起きたか: 実体を `bon2/.dev-partner/` に置き、`~/.claude/skills/dev-partner` と `~/.claude/dev-partner` をシンボリックリンクにした。リンクはリポジトリの SessionStart フックが毎回張り直す。
- 原因分類: うまくいった理由は、指定されたパスをそのまま作る前に「その場所はセッションをまたいで残るか」を確認したこと。
- 次回のルール: 永続化が必要なデータを書く前に、置き場所が揮発しないか確認する。揮発するなら Git 管理下に実体を置く。
- 対応: `.dev-partner/install.sh`、`.claude/hooks/dev-partner-session-start.sh`

## L-002 [成功] 公開リポジトリ＋GitHub Pages では作業ファイルをドット始まりのフォルダに置く（2026-11-19 / P-000）
- 状況: bon2 は公開リポジトリで、GitHub Pages が有効（main ブランチの内容が店舗サイトとして公開される）。
- 何が起きたか: 作業ファイルの置き場所を `.dev-partner/` にした。GitHub Pages の Jekyll はドットで始まるフォルダを公開しないので、`.md` が店舗サイトのページとして公開される事故を避けられる。
- 原因分類: うまくいった理由は、置く前に公開範囲（visibility / has_pages）を確認したこと。
- 次回のルール: Webサイトのリポジトリに作業ファイルを置くときは、公開範囲とビルド対象を先に確認する。
- 対応: なし（L-001 と同じ構成で対応済み）
