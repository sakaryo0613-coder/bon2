# backlog — 次に作る候補

**区分**
- 【拡張】既存の成果物に機能を足せば済むもの
- 【新規】独立したモノとして作るべきもの
- 【環境】AI自身の開発環境・ツールの改善

判定基準：使う人・使う場面・扱うデータが既存と同じなら【拡張】、違うなら【新規】。迷う場合は両案を書いて比較する。

**価値**（1〜5）
- 1: あれば便利
- 2: 月1回程度の手間が減る
- 3: 毎週の作業が楽になる、または品質が上がる
- 4: 毎週の作業時間が大きく減る、または失敗を確実に防ぐ
- 5: 売上・成果に直結する、またはそれがないと他が進まない

**工数**（1〜5。AIの作業とユーザーの確認を含む）
- 1: 1セッション以内（〜1時間）
- 2: 半日
- 3: 1日
- 4: 2〜3日
- 5: 1週間以上

**優先度** = 価値×2 − 工数
- 高: 6以上
- 中: 3〜5
- 低: 2以下

表には `高(7)` の形で書く。`dp.py score <価値> <工数>` で計算できる。

**状態**：進行中／選択待ち／未着手／保留／完了／見送り

**上位N件の決め方**：進行中 → 選択待ち → 未着手（スコアの高い順）。`dp.py top 3` で表示する。

## 詳細

### B-001 【新規】YouTube動画の切り抜き自動化ツール
- 起点: ユーザーの依頼（2026-11-19）
- 新規とした理由: 既存の P-001（店舗サイト）とは、使う人（動画の運用者）、使う場面（動画を公開した後の編集作業）、扱うデータ（動画・音声・文字起こし）がすべて違う。
- 価値4の根拠: 長尺1本からショートを作る作業（1本あたり手作業30〜60分が一般的）を、毎週繰り返し減らせる。
- 工数4の根拠: 文字起こし、見どころの選定、縦型への変換と字幕、レビュー画面の4つの部品があり、2〜3日かかる。
- 次のアクション: 候補A〜Eから選択待ち（推奨D。Q1〜Q3の回答も受付中）→ 選ばれたら手順3（works/youtube-clipper/02-spec.md）

### B-002 【環境】数値調整パネル（tune-panel）
- 起点: SKILL の「感覚的な調整」への対策例。見た目の案件では、余白・文字サイズ・秒数などの微調整がほぼ毎回起きる。
- 作る条件: 2回以上使う見込みあり。ただし汎用品を先に作るより、**最初に感覚的な調整でやり直しが起きた案件の数値を題材にして作る**ほうが、本当に必要な形になる。
- 仕様の方向: 対象ページを iframe で表示し、CSS変数・数値をスライダーやカラー入力で変える。「変更した箇所だけをプロンプト化してコピー」ボタンで、変更前→変更後の一覧を出す。
- 価値3の根拠: 見た目の案件のたびに、往復のやり取りが2〜3回減る。
- 工数2の根拠: 1ファイルのHTMLツールで済む。
- 次のアクション: 次の見た目の案件で、感覚的な調整が発生したら着手する

### B-003 【環境】dev-partner を bon2 以外のセッションやローカルPCでも使えるようにする
- 起点: P-000 を作ったときに分かった制約。クラウドでは `~/.claude` が揮発し、現在の構成では bon2 リポジトリのセッションでしか dev-partner が自動で有効にならない。また、店舗サイトのリポジトリ（公開）に開発の記録が同居している。
- 拡張か新規か: P-000 の改善なので【環境】に分類した。使う人・場面・データは同じ。
- 改修内容:
  1. 専用リポジトリ（例: `dev-partner`、非公開）を作り、`.dev-partner/` をそこへ移す。リポジトリの作成はユーザーが行う。
  2. クラウド環境のセットアップスクリプトに、そのリポジトリの取得と `install.sh --global` を登録する。
  3. ローカルPCでは `git clone` してから `install.sh --global` を実行する。
- 価値4の根拠: 全セッションで backlog の提示と手順が有効になる。公開リポジトリから開発メモを外せる。
- 工数2の根拠: スクリプトは用意済み。残りはリポジトリの作成・移行・環境設定の確認だけ。
- 次のアクション: ユーザーが専用リポジトリを作るか判断する（作らない場合は bon2 のまま運用）
