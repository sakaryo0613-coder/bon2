# B-013 clipper のアプリ内更新 — 仕様（02-spec）

## 流れ
```
main に反映 → CI（Windows）でビルド・テスト → 版 0.3.<run番号> の Release「clipper-v0.3.N」に clipper-setup.exe を載せる
アプリ: ホームを開く → /api/update（GitHub の releases を確認。10分キャッシュ）→ 新しければお知らせ
  →「更新する」→ %LOCALAPPDATA%\clipper\updates\ にダウンロード（進み具合を表示）
  → clipper-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE=1 を起動 → アプリは終了
  → インストーラーが上書き → /UPDATE=1 のときだけ clipper を自動で起動 → 新しい窓が開く
```

## 数値と根拠
| 項目 | 値 | 根拠 |
|---|---|---|
| 版の番号 | `0.3.<CI の実行番号>`。比較は数値で行う | 実行番号は必ず増えるので、比較が単純になる |
| 版の埋め込み | ビルド時に `clipper/_version.json` を書き、アプリはそれを読む。ソースから動かすときは `dev` | exe とインストーラーの版を一致させる |
| 確認のタイミング | ホームを開いたとき。結果は**10分キャッシュ**、タイムアウト**5秒**。失敗したら何も表示しない | GitHub API の未認証の上限（1時間60回）に十分余裕がある。オフラインでも邪魔をしない |
| 確認先 | `https://api.github.com/repos/sakaryo0613-coder/bon2/releases?per_page=20` のうち、タグが `clipper-v` で始まるもの。環境変数 `CLIPPER_UPDATE_URL` で差し替え可能（テスト用） | bon2 は他の用途もあるので、プレフィックスで絞る |
| ダウンロード | 1MB ずつ。タイムアウトは60秒（無通信）。終わったらサイズを確認し、GitHub が sha256 を返していれば照合 | 壊れたファイルでインストーラーを起動しない |
| 起動からの終了 | インストーラーを起動した**1秒後**にアプリが終了する | 上書き対象の clipper.exe を開放する |
| 失敗時 | ダウンロード・照合に失敗したら、今の版のまま「更新できませんでした（理由）」を表示。インストーラーは起動しない | 今の版を壊さない |
| 古い窓 | 「更新しています。終わると新しい窓が開きます。この窓は閉じてかまいません」と表示 | 新しいアプリは別のポートで起動するため、古い窓は再利用できない |

## 合格基準
| # | 基準 | 判定方法 | 場所 |
|---|---|---|---|
| AC1 | 版の比較・Release の読み取り（`clipper-v` 以外は無視、下書きとプレリリースは無視） | 単体テスト | ローカル |
| AC2 | 新しい版があるとホームにお知らせが出て、「更新する」でダウンロードの進み具合が出る。ないときは何も出ない | Playwright（更新元はテスト用に差し替え） | ローカル |
| AC3 | ダウンロードが壊れていたら（sha256 の不一致・サイズ0）インストーラーを起動せず、理由を表示する | 単体テスト | ローカル |
| AC4 | ホームに今の版が表示される | Playwright | ローカル |
| AC5 | **Windows で古い版から新しい版に、アプリ内の更新で上書きでき、更新後にアプリが自動で起動する** | CI: 旧版を入れる → ローカルの擬似 Release を見せて `clipper.exe --update-now` → 版が新しくなり、clipper.exe が再び動いていることを確認 | Windows |
| AC6 | main への反映で Release が作られ、ログインなしで `clipper-setup.exe` をダウンロードできる | CI の公開ジョブ ＋ 公開後に URL を取得して確認 | GitHub |
