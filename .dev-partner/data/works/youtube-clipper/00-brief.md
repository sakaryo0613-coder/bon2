# B-001 YouTube動画の切り抜き自動化ツール — 要件（00-brief）

状態: 完了（案D 第1段階 → P-002）。経緯は 01-candidates.md → 02-spec.md → 03-verify.md

## 目的（推定）
長尺のYouTube動画（配信アーカイブ・トーク・紹介動画など）から、Shorts / TikTok / Reels 向けの短いクリップを、最小限の手作業で毎週作り続けられるようにする。

## ターゲット（推定）
- 自分のチャンネル、または切り抜きの許諾を得たチャンネルを運用する個人
- カット位置探し・縦型への切り出し・字幕入れを、動画編集ソフトで毎回手作業したくない人

## 成功指標（仮置き。数値は手順3で確定する）
| 指標 | 目標 | 根拠 |
|---|---|---|
| 人の作業時間 | 60分の動画1本から、公開できるクリップ5本を **15分以内** | 手作業では1本あたり30〜60分かかるのが一般的。その1/10以下を狙う |
| 候補の採用率 | AIが出した候補の **50%以上**を採用 | 半分以上が外れだと、確認の手間が手作業を上回る |
| 処理時間 | 60分の動画で **30分以内**（放置でよい。一般的なノートPCのCPUで） | ローカルの文字起こし（faster-whisper small 相当）は、CPUで動画の長さの0.3〜0.5倍程度かかるため |
| 書き出し品質 | 1080×1920・字幕を焼き込む・文の途中で始まったり終わったりしない | Shorts の推奨解像度。途中で切れると視聴が続かない |

## 前提・仮説（否定されない限り、この前提で進める）
- H1 素材は**自分の動画、または切り抜きを許諾された動画**。各チャンネルの切り抜きガイドラインに従い、出典表記を入れられるようにする。権利のない動画は対象外。
- H2 実行場所は**ユーザーのPC（Mac/Windows）**。処理は Python + ffmpeg、画面はローカルで開くブラウザ画面にする。クラウド環境は YouTube への接続制限と処理の重さから向かない。
- H3 入力は「動画URL」または「動画ファイル」。
- H4 文字起こしはローカル（faster-whisper）で行う。区間の採点とタイトル案は Claude API で作る（APIキーはユーザーが用意する）。
- H5 日本語の動画が中心。
- H6 1回に処理する動画は1本で、長さは最大3時間。
