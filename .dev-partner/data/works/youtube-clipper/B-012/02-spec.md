# B-012 Twitch の URL 取り込みとチャットの盛り上がり — 仕様（02-spec）

## 流れ
```
ホーム: 「または Twitch の URL」に貼る → /api/url/check（通信しない判定）→ ✓ なら「候補を作る」が押せる
「候補を作る」→ /api/jobs {url}
  ① 確認（yt-dlp で題名・配信者・長さ。配信中なら断る）
  ② チャット（GraphQL。カーソル送り → 断られたら時刻送り。取れなければ警告を出して言葉だけで続ける）→ chat_messages.json
  ③ 動画（yt-dlp。720p まで、断片を8並列）→ 作業フォルダ/source.mp4
  ④ 文字起こし → 候補（チャットの加点つき）→ レビュー画面（理由に「チャット ×2.3」）
```

## 数値と根拠
| 項目 | 値 | 根拠 |
|---|---|---|
| 画質の上限 | 720p | 帯レイアウト（既定）は元の動画を幅1080に縮めて置く。1080p と見た目がほぼ同じで、取得量が約半分 |
| 断片の並列数 | 8 | yt-dlp の HLS の取得は、1本ずつだと回線を使い切れない。8で家庭の回線（100Mbps）をほぼ使い切る |
| チャットの数え方の幅 | 10秒 | 盛り上がりは数秒〜数十秒続く。1秒では件数が少なすぎてぶれる |
| 平常の基準 | 前後5分の中央値（下限 10秒に1件） | 配信の流れ（開始直後・終盤）で流速が変わるので、全体の平均は使わない。中央値なら、山そのものに引っ張られない。下限は、チャットが少ない配信で2〜3件を「×5」と誤るのを防ぐ |
| 遅れ | 区間の 3〜12 秒後ろを数える | 配信の遅延（低遅延モードで2〜5秒）＋読んで打つ時間。下調べの実データでも、話題の数秒後に「おかえり」が並んだ |
| 盛り上がり | 平常の1.5倍以上、かつ5件以上 | 1.5倍未満はふだんのゆらぎ。5件未満は偶然でも起きる |
| 加点 | 最大+25（×1.5で+5、×3.5以上で+25）×山をどれだけ含むか。チャットの笑い（30%以上）で+5 | 言葉の「笑い」の加点（最大+24）と同じ重さにし、チャットだけで候補が埋まらないようにする。山の一部にかかるだけの区間（前の話題をくっつけた区間）は加点を減らす（手順4の試作で、話題をまたいだ区間が選ばれたため） |
| Claude への渡し方 | 盛り上がった文の末尾に「💬×N」（1.5倍以上・3件以上）。system に意味を1段落 | 文単位で渡すと、Claude が話の区切りとチャットの両方を見て選べる |
| 進み具合 | ①②は件数、③は断片の数で％ | 3時間の取得は10分前後かかる。止まって見えないようにする（B-004 の教訓） |

## 合格基準
| # | 基準 | 判定方法 | 場所 |
|---|---|---|---|
| AC1 | URL の判定: アーカイブは受け付け、クリップ・チャンネル・YouTube・その他は理由と次の操作を1文で返す | 単体テスト（12通り） | ローカル |
| AC2 | チャットの取得: カーソル送りが断られたら時刻送りに切り替え、重複なく最後まで取る。登録済みの問い合わせが消えたら本文を送る。`until` で途中まで | 単体テスト（偽の GraphQL） | ローカル |
| AC3 | チャットの集計: 遅れを考えて山を見つける。静かな区間・チャットの少ない配信では加点しない。山の一部だけの区間は加点が減る | 単体テスト | ローカル |
| AC4 | 採点: 見本の動画で、雑談の区間にチャットの山を置くと、その話題のまとまり（話題をまたがない）が候補に入り、理由に「チャット ×N」が出る。チャットがなければ今までと同じ結果 | 単体テスト（見本＋合成チャット） | ローカル |
| AC5 | Claude への入力に「💬×N」と説明が入る（チャットがないときは入らない） | 単体テスト（偽のクライアント） | ローカル |
| AC6 | ホーム: URL を貼る → 「候補を作る」の **2操作**で、確認・チャット・動画・文字起こし・候補の段階が順に出て、レビュー画面に進む。理由に「チャット ×N」が出る | Playwright（取得部分は差し替え） | ローカル |
| AC7 | 失敗の案内: 取り込めない URL は貼った時点で理由を出す。取得の失敗（期限切れ・サブスク限定・配信中・接続）は1文で出る。チャットだけ失敗したら警告を出して続ける | 単体テスト＋ Playwright | ローカル |
| AC8 | ホームの主要ボタン（`#pick` `#start`）が 1280×680・1024×680 のファーストビューに入り、下端から48px以上空いている（更新の帯が出ていても） | `shot.cjs --must-see` ＋スクショの目視（足す前と後を比較・L-014） | ローカル |
| AC9 | **Windows のアプリ（同梱の yt-dlp）で、本物の Twitch からアーカイブの情報・チャット・動画の冒頭を取れる** | CI: `clipper.exe --twitch-probe` | Windows |
| AC10 | 既存のテスト・自己テスト・インストール・更新のテストが通る | CI | Windows |
| AC11 | 実際のアーカイブで、候補の質（チャットの効き目）を確かめる | ユーザーの PC（「更新する」で入れて試す） | 実機・未検証になる |

## 未検証になるもの
- AC11 は、ユーザーの PC と実際のアーカイブで確かめる。CI では公開のアーカイブの冒頭（情報・チャット10分・動画20秒）だけを取る
