# B-012 Twitch のアーカイブを URL で取り込み、チャットの盛り上がりを採点に使う — 要件（00-brief）

## 手順0の宣言
- 読んだもの: learnings L-001〜L-015、toolkit/INDEX.md、knowledge/windows-app.md・web-ui.md・short-video.md
- 守る教訓:
  - L-010: Twitch はこの環境から接続できない（twitch.tv・gql.twitch.tv が遮断）。接続しない部分（URL の判定・チャットの集計・採点・画面）は手元でテストし、取得そのものは GitHub Actions で通す
  - L-011・L-015: Windows のアプリに同梱して、Windows の CI で本物の Twitch から取れることを確かめる
  - L-014: ホームに URL の欄を足すので、足す前と後のスクショを並べて見る。`--must-see` の下端の警告も見る
  - L-009: 使う人・環境・目的は P-002 で確認済み（本人とスタッフ・Windows・本番で使う可能性あり）
- 使うツール: shot.cjs（`--must-see`）、cilog.py、dp.py

## 目的
Twitch の配信アーカイブから、**URL を貼るだけで**切り抜きの候補を作れるようにする。チャットの盛り上がりを手がかりにして、言葉だけでは拾えない見どころ（ゲームの山場・視聴者が沸いた瞬間）も候補に入れる。

## ターゲット
- ユーザー本人とスタッフ（非エンジニア・Windows）。P-002 と同じ
- 自分の Twitch のアーカイブ、または切り抜きを許可された配信者のアーカイブ

## 成功指標（数値）
| 指標 | 目標 | 根拠 |
|---|---|---|
| 操作 | URL を貼る → 「候補を作る」の **2操作**で、ファイルの準備なしに候補づくりが始まる | B-008 の「3操作以内」より少なくする（ファイル選択がなくなる分） |
| 取得の時間 | 3時間のアーカイブで、動画とチャットの取得が **回線100Mbpsで15分以内** | 720p で約3.5〜6Mbps → 3時間で約5〜8GB。100Mbps なら7〜11分。文字起こし（3時間で約60分）より短ければ全体の律速にならない |
| チャットの効き目 | チャットが急に増えた区間（平常の2倍以上）を、候補の上位に入れる。理由に「チャット ×2.3」のように倍率を出す | 人が見ても「なぜ選ばれたか」が分かるように |
| 失敗の分かりやすさ | 取れないとき（期限切れ・サブスク限定・URL の誤り）は、何が原因でどうすればよいかを1文で出す | B-004 の実機で、止まって見える失敗が一番困った |

## 前提と仮説（否定されない限り、この前提で進める）
1. 対象の URL は Twitch のアーカイブ（`twitch.tv/videos/<番号>`）。ハイライト・アップロードも同じ形なので含める。クリップ（`clips.twitch.tv`）とチャンネルの URL は対象外で、案内を出す
2. YouTube の URL は今回も対象外（利用規約。Studio からのダウンロードを案内する）
3. サブスク限定のアーカイブ（ログインが必要）は対象外。案内を出す
4. Twitch のアーカイブは期限がある（通常7日、アフィリエイト14日、パートナー等60日）。画面で「早めに取り込む」と案内する
5. 画質は 720p を上限にする。帯レイアウト（既定）では、元の動画を幅1080に縮めて置くので、1080p と見た目がほぼ変わらず、取得量が約半分になる
6. チャットは配信の映像より遅れて反応する（配信の遅延＋打つ時間）。区間の評価は、その区間より **3〜12秒後ろ**のチャットで行う
7. Twitch の利用規約は、提供された手段以外でのダウンロードを広く認めていない。自分のアーカイブは「動画プロデューサー」からダウンロードできる。URL の取り込みは**自分のアーカイブ、または切り抜きを許可されたもの**に限ると画面と説明書に書く（YouTube と同じ扱い）
