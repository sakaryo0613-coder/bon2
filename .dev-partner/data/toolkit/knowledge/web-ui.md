# ナレッジ: ローカルWebアプリの画面（HTML/JS）とその自動テスト

画面のあるツールを作る案件の手順0で読む。B-001 と B-008 で実際につまずいた点が元になっている。

## 重ね表示（ガイド・スポットライト・ダイアログ）
- `position: sticky` / `fixed` の要素は、**z-index がなくても独自の重なり順（スタッキングコンテキスト）を作る**。その中の要素に z-index を付けても、暗幕より前には出ない（B-008: ヘッダー内のボタンを強調できなかった）
- 構成は「暗幕 z20 < 強調する要素 z21 < 説明の箱 z22」とし、**外枠（.guide）自体は重なり順を作らない**ようにする。強調する要素の祖先（sticky のヘッダー・パネル）にも z-index を付けて前に出す
- 説明の箱は、強調している場所と**反対側**に置く。中央固定だと強調箇所と重なる
- 表示中はキーボードショートカットを止める（ガイドを読みながらキーを押して操作が進む事故を防ぐ）
- 実装例: `works/youtube-clipper/app/clipper/review.html` の `showGuide()`

## 主要ボタンをファーストビューに入れる
- 想定する最小の表示領域で `shot.cjs --must-see "#ok,#ng"` を通す。ノートPCでよくある 1920×1080・表示倍率150% は、実質 1280×720。タイトルバーとタスクバーを引くと **1280×680**
- 長い一覧や文字起こしの「下」に操作ボタンを置かない。タイトルの直下に置く（B-001: 1280×800 で画面外だった）

## Playwright での自動テスト
- サイズのない外枠（子が全部 `position: fixed`）は「見えない」と判定される。待つのは中の箱（`#guide:not([hidden]) .gbox`）にする
- 画面に重なった要素がクリックを奪うと `... intercepts pointer events` で止まる。重なり順の不具合のサインなので、テストを直さずに画面を直す
- ネイティブのファイル選択画面は自動操作できない。サーバー側の選択処理を差し替え可能にしておく（`app.picker = lambda kind: path`）
- **観測が結果を変えるテストに注意**: 「通知が途絶えたら終了する」を、サーバーへの問い合わせで確認すると、その問い合わせ自体が通知になって終わらない。内部のフラグで確認する（B-008）
- ブラウザの初回表示の状態（localStorage の「表示済み」）は、テストごとに新しいブラウザコンテキストで始まる。再読み込み後の挙動もテストする

## ローカルサーバー
- 127.0.0.1 だけで待ち受け、ポートは空きを自動で選ぶ（`port=0`）
- 動画は Range 対応で返さないとシークできない
- 窓を閉じたら終了させたいときは、画面から10秒ごとに生存通知を送り、60秒途絶えたら終了（処理中は終了しない）
- 例外は必ず画面に案内として返す。ファイル選択画面（tkinter）は画面のない環境では開けない
